# מערכת סוכנות כושר (FitStudio) - בוט וצ'אט

ברוכים הבאים למערכת FitStudio! מערכת זו מיועדת לנהל את האינטראקציה בין מתאמנים לבין סטודיו הכושר באמצעות בוט AI מבוסס Gemini, וכוללת ממשק משתמש נוח למתאמנים וכלי ניהול נתונים בסיסיים לסטודיו.

## מטרת התוכנה

המטרה של הפרויקט היא לספק שירות לקוחות ואינטראקציה אוטומטית למתאמנים קיימים וללידים (מתאמנים פוטנציאליים). הבוט יודע לנהל שיחה חכמה עם המתאמן, לזהות אותו באופן בטוח, לשמור על אבטחת מידע, לענות על שאלות כלליות (עלויות, שעות פעילות), לאחזר מידע על תורים (WOD) ולהציע רישום לאימונים, וכל זה תוך ניהול מצב (State Management) שזוכר את היסטוריית השיחה ואת השלב בו נמצא הלקוח.

## שלבי הפיתוח

1. **תכנון ארכיטקטורה ומסד נתונים**: יצירת סכמת נתונים לניהול מנויים (Members), לידים (Leads) ואימונים (WOD Classes & Registrations).
2. **הקמת מסד נתונים (SQLite)**: שימוש ב-SQLite כדי לשמור את נתוני הלקוחות, עם סקריפטים כמו `seed_data.py` להזרקת נתוני בדיקה.
3. **פיתוח ה-Agent והלוגיקה העסקית**:
   - ניהול שלבי אימות קשיחים כדי לא לחשוף מידע אישי.
   - אימות תעודת זהות ושם בצורה מאובטחת.
   - אכיפת הגבלת מספר ניסיונות אימות (עד 3 ניסיונות) ולאחריה חסימת השיחה מטעמי אבטחה.
4. **אינטגרציה ל-Gemini API (NLU)**: שימוש ב-AI כדי לחלץ כוונות (Intents) ולהבין את הטקסט של המשתמש בצורה גמישה גם בשפה טבעית, וכן לייצר תגובות טבעיות למשתמש.
5. **בניית ממשק משתמש (Streamlit)**: פיתוח ממשק Web נוח ב-Streamlit שמאפשר ללקוחות להקליד שאלות ולקבל תשובות מהבוט בצורה של צ'אט.
6. **Dockerization**: עטיפת האפליקציה בקונטיינר של Docker להרצה קלה ואחידה בכל סביבה.
7. **כתיבת תיעוד ודוחות (Logs)**: הקמת מערכת לוגים המאפשרת ניטור ומעקב מלא אחר שגיאות ושלבי ביצוע לצורך דיבוג קל יותר (Auditing).

## שיטות ופונקציות מיוחדות

### ניהול מצב (State Management) - `ConversationState`
מחלקה ב-`chatbot/state.py` השומרת את ה"זיכרון" של הצ'אטבוט. 
היא יודעת מהו שלב השיחה (GREETING, IDENTIFY_NAME, IDENTIFY_ID, ANSWERED, BLOCKED, RAG_MODE). הבוט משתמש בה כדי לא לשאול את הלקוח שאלות שכבר ענה עליהן וכדי לאכוף את הגבלת הניסיונות (`auth_attempts`).

### מנגנון אבטחה ואימות קשיח
כדי לענות על דרישות אבטחה חמורות:
- `db_service.verify_member_identity` ו-`db_service.authenticate_member`: מוודאים את השם ומספר תעודת הזהות כנגד הדאטה בייס בצורה ישירה.
- **אפס חשיפת מידע**: הבוט לעולם אינו עונה לשאילתות ספציפיות על אימונים או תורים ללא אימות תעודת זהות מוצלח (verify_member_identity מחזיר True).
- במידה ויש שמות חופפים - המערכת לא מנחשת ומבקשת מהמשתמש להזדהות ספציפית באמצעות מספר זיהוי ייחודי.

### ניתוח שפה טבעית (NLU) - `chatbot/nlu.py`
אחראי לחילוץ כוונות ומידע מהמשתמש:
- `extract_intent`: פונה ל-Gemini API עם הנחיות (System Prompt) ספציפיות שמכריחות את המודל להחזיר JSON עם ה-Intent המדויק (למשל `IDENTIFY_RESPONSE`, `APPOINTMENT_INQUIRY`) והפרמטרים הנדרשים כגון תאריכים ותעודות זהות.

### ארכיטקטורת סוכן (Agent) - `ChatbotAgent`
מחלקה שמרכזת את כלל הפעילות:
- פונקציית הליבה `process_message` מקבלת הודעה, רושמת לוג מסודר (`logger`), מעבירה לניתוח ב-NLU, ומנתבת את הבקשה לאחת הפונקציות הייעודיות (`_handle_identify_name`, `_handle_identify_id`, `_handle_answered`) בהתאם לשלב השיחה הנוכחי. 
- היא מנהלת אוטומטית שגיאות ושומרת על זרם העבודה (Try/Except logs).

## הרצת המערכת

יש לוודא שיש לכם קובץ `.env` עם המפתח `GEMINI_API_KEY`.
כדי להריץ מקומית יש להפעיל:
```bash
streamlit run app.py
```
כדי לבדוק את הלוגיקה והאבטחה ללא ה-API של גוגל, ניתן להריץ את סקריפט הבדיקות:
```bash
python test_chat.py
```
